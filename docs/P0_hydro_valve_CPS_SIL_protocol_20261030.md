# AEFC 水力发电阀门流量调节 CPS 软件在环实验协议（2026-10-30）

## 1. 实验定位与证据边界

本实验在 IEEE 39 节点原生仿真之外，增加一组**水力发电 CPS 分层架构的软件在环（SIL）实验**。模型按实验平台的企业层、监控层、站控层和物理层组织，并将 AC1、AC2 明确建模为两个阀门开度—支路流量调节执行机构。

必须区分以下事实：

- 当前 GitHub Actions 运行环境不连接实验室 HMI、ES、S7-300、S7-1500 或 AC1/AC2，也不下发真实控制命令。
- 当前水力过程参数为归一化、未标定的模型参数，不是由真实水轮机、管路或阀门辨识得到的参数。
- 因此，本实验只能称为“基于水电 CPS 平台拓扑的归一化软件在环实验”，不能称为真实 PLC/HIL 实测或电站现场实验。
- 本实验评价 AEFC 机制在第二类物理过程模型中的行为，不替代 IEEE39 原生实验，不重新认证 G1、G3 或 G5。
- 本实验使用简化的模型驱动局部更新梯度，不执行完整深度 actor–critic FRL 训练；结果属于机制级迁移证据。

## 2. 平台结构与变量映射

| 层级 | 平台组件 | SIL 中的职责 |
|---|---|---|
| 企业层 | MH1、MH2、Router、Corporate Network | 管理信息与企业网络入口的逻辑表示 |
| 监控层 | HMI、ES、Firewall、Monitoring Network | HMI 监控过程；ES（Engineering Station，工程师站）生成/转发运行指令；表示观测与指令通信路径 |
| 站控层 | S7-300、S7-1500、工业防火墙、Control Network | 两个 PLC 的站级控制逻辑及可信本地测量路径的逻辑表示 |
| 物理层 | AC1、AC2、CAN bus、Hydraulic Process | AC1/AC2 阀门开度控制两个支路流量，两个支路通过共同水头和水轮机转速耦合 |

ES 的全称为 **Engineering Station（工程师站）**，不是 Execution System。S7-300 与 S7-1500 的具体 I/O 到 AC1、AC2 的现场通道归属，须由真实 PLC tag/I/O 清单确认；当前 SIL 不擅自指定一一映射。

物理子系统数设为 M=2，分别对应 AC1、AC2 所调节的两个水流支路。联邦客户端数独立设为 N=5，其中至多 f=1 个为拜占庭客户端，满足 N>2f。这五个客户端是 SIL 中的逻辑数据分区/学习客户端，不代表平台上存在五台物理 PLC 或五个真实硬件节点。

## 3. 归一化水力过程模型

状态向量为

[
x=[h,q_1,q_2,\omega,\alpha_1,\alpha_2]^\top,
]

其中 h 为归一化水头，q_i 为第 i 个支路流量，omega 为归一化水轮机转速，alpha_i 属于 [0,1]，表示阀门实际开度。控制输入为

[
u=[u_1,u_2]^\top,
]

分别表示 AC1、AC2 的目标阀门开度。连续时间的简化过程关系为

[
\dot h=\frac{Q_{\mathrm{in}}-q_1-q_2}{A_r},
]

[
\tau_q\dot q_i=C_i\alpha_i\sqrt{\max(h,h_{\min})}-q_i,
]

[
\dot\alpha_i=\operatorname{clip}\left(\frac{u_i-\alpha_i}{\tau_v},-r_v,r_v\right),
]

[
J\dot\omega=\eta_hh(q_1+q_2)-P_L-D_\omega(\omega-1).
]

实验使用前向 Euler 离散化，Delta t=0.05 s，每回合 480 个采样点（名义仿真时长 24 s）。参数、额定点、状态边界及攻击幅值完整记录在 configs/hydro_valve_cps_sil_20261030.json 和每次运行生成的 frozen_config.json 中。

额定流量为 q_1*=0.48、q_2*=0.42，额定水头和转速均为 1。状态安全盒为：

- h 属于 [0.92,1.08]；
- q_1 属于 [0.38,0.58]，q_2 属于 [0.33,0.51]；
- omega 属于 [0.97,1.03]；
- alpha_1、alpha_2 属于 [0,1]。

策略参数 theta=[K_p1,K_i1,K_p2,K_i2]^T 表示两个阀门流量回路的 PI 增益。各逻辑客户端根据本地测量构造一步流量跟踪损失的解析梯度；服务器执行逐坐标截尾聚合及 AEFC 的信念、授权、部署和执行处理。

## 4. 信任边界与攻击配置

### 4.1 可信测量假设

物理观测攻击作用于 HMI/ES 的监控观测路径；站控 PLC 的本地过程测量通过独立的可信测量路径提供给执行屏障。该本地测量在 SIL 中叠加有界归一化噪声，幅值不超过 0.01。执行屏障不读取真实仿真状态，而使用该 PLC 本地测量估计。若真实部署中 PLC 本地测量链路也可被攻击，则当前安全屏障输入假设不成立，必须另行建模。

### 4.2 主实验四种场景

| 场景 | HMI/ES 观测攻击 | 联邦知识投毒 | 屏障后阀门命令扰动 |
|---|---|---|---|
| clean | 无 | 无 | 无 |
| physical | 偏置与 4 步重放 | 无 | 每个阀门通道有界扰动 ±0.08 |
| knowledge | 无 | 5 个逻辑客户端中 1 个提交异常证据和模型更新 | 无 |
| joint | 偏置/重放 | 同时发生 | 每个阀门通道有界扰动 ±0.08 |

攻击窗口为第 120–239 个采样点（含端点），即 120 个采样点。观测偏置、重放混合权重、拜占庭证据偏置、更新替换比例、命令扰动上界均在冻结配置中明示。仿真器知道攻击注入位置以生成攻击；在线 PATBU/聚合逻辑不读取隐藏的恶意客户端索引。

### 4.3 动作接口攻击的实验边界

动作授权之后、最终执行屏障之前的命令替换不纳入本轮四场景主矩阵。该攻击需要单独冻结注入幅值、执行屏障可行性条件和独立确认种子，不与本轮主实验合并；本轮不据此作出 G5 认证结论。


## 5. 方法与预注册参数

主矩阵比较七种方法：FedRL、RobustAgg、AEFC-no-PATBU、AEFC-no-Gate、AEFC-no-TGOPA、AEFC-no-Shield 和 AEFC-Full。五个逻辑客户端、一个拜占庭客户端；逐坐标截尾聚合满足有效参与数大于 2f。

冻结参数包括：PATBU 证据/观测/先验融合权重 0.65/0.15/0.20，最小部署/信任阈值 0.90，风险评分阈值 0.004，学习步长 0.010，更新裁剪阈值 0.020，部署信任域半径 0.005，执行屏障下游命令扰动包络 0.08。完整参数以 JSON 配置为准，论文不得仅从文字重建参数。

每个 seed 的外源流量、负荷、传感器噪声、客户端噪声和更新噪声由同一确定性随机流生成，并在不同方法间复用，形成匹配工况。seed 是确定性仿真条件编号，不应被表述为真实电站独立运行次数。

## 6. 样本规模、判据与统计

- 正式确认种子：220–239；此前用于机制探索的 seed 200 不进入正式确认集。
- 4 个主场景 × 7 种方法 × 20 个匹配 seed = 560 回合。
- 每回合 480 点，总计 268,800 个采样点。
- 统计基本单位为完整 seed 回合；回合内采样点不作为独立样本。
- 参数动态影子仅用于离线评价，使用同一物理轨迹上的干净证据和对应方法的更新算子，不参与在线控制。
- 如报告经验纠正，必须先在攻击结束时处于容差外，再进入 epsilon=0.001 并连续保持 20 点。当前主矩阵不是专门的 G3 冻结目标确认实验，不因某些影子误差下降而宣称 G3 得到验证。
- 统计比较采用同 seed 配对差值；bootstrap 以 seed 为重采样单位。时间采样点、客户端报告数和攻击窗口数不增加独立样本量。

## 7. 输出与独立审计

每个回合保存 480 行 JSONL，逐 seed 另存摘要。审计脚本 analysis/audit_hydro_valve_cps.py 不重新运行模型，只读取原始轨迹并复算状态越界、执行器饱和、屏障可行性、门控拒绝、参数移动、动态影子误差、物理跟踪误差和执行修正量；随后生成 per_seed_metrics.csv、paired_effects.csv、raw-traces.tar.gz、SHA256 和 audit_report.json。

正式运行由 GitHub Actions Python 3.11 执行，不安装 MATLAB，也不访问真实 PLC。归档审计通过只表示代码运行、轨迹完整性和派生统计复算通过，不等同于真实硬件验证、模型参数标定或 G1/G3/G5 形式认证。

## 8. 真实平台后续校准所需数据

在将 SIL 结论提升为真实 PLC/HIL 实验前，至少需要：AC1/AC2 的实际开度反馈与命令范围、阀门开度—流量曲线、管路/水头参数、流量和水头传感器量程与采样周期、转速与负荷数据、S7-300/S7-1500 的 I/O tag 对照、PLC 扫描周期、网络路径与时间戳、屏障后命令链路的攻击/故障包络，以及现场安全联锁和人工急停流程。未取得这些数据前，不把当前归一化参数解释为真实设备参数。

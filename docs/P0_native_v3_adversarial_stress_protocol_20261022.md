# AEFC v3 独立对抗压力测试协议（2026-10-22）
**独立于80–119确认集、独立于冻结控制器。** 此实验仅在种子64–71的红队扰动下测试假设失效边界；任何弱结果都不删除，也不能据此重新优化80–119的冻结确认版本。

- 原算法源：commit `b2bf6a079f05d1f0642f9300fcab027869b6a6e9`，方法 `AEFC-Unprivileged`、`AEFC-Checkpoint`、`AEFC-ContractiveReentry`。压力机制使用**独立复制**的 `AEFCNativeRecoveryStressController.m` 追加攻击接口，冻结原类 `AEFCNativeOnlineRecoveryController.m` 及原参数JSON保持不变。
- 配对样本：3个压力场景×3方法×8种子（64–71）=72回合，原生 R2024b IEEE39每回合480点，共34,560采样点。训练/门限/近端λ=0.08/ε=0.001/hold=20均保持冻结实验设置；对抗压力成功失败均须保留。
- 场景1 **两名拜占庭客户端串谋**：仅在t15–43替换客户端1、2收到的知识/梯度；使用诚实5个报告的每维中位基线+0.22知识偏移、-0.18梯度偏移，并伪装时龄0（攻击机制内部用于构造负例，不作为在线信任源）。测试两份协调且温和的有限值报告能否绕过一致性过滤及其后的恢复误差。严格区分“2/7串谋”与更强的“5/7合谋”；这里不测5/7。
- 场景2 **长时间观测偏置**：在t15–180对控制器接收到的4维归一化观测施加幅度0.25的确定性偏置，物理真实量和离线干净报告不被修改；**实际攻击结束时刻t180**，只能从t181起计算攻击后纠正，绝不能以原t44判定恢复。
- 场景3 **检查点完整性故障**：在t10存储原始检查点，t20模拟攻击者改写在线检查点θ_a += [0.06,-0.06,0.06,-0.06]，L2幅度0.12，无真实抗篡改签名/校验；仅在线控制/在线代理使用被篡改锚；**离线干净反事实仍使用原始t10未篡改锚**，避免使比较参照随攻击一起偏移。t20–43标记压力持续作用，44起评估。若方法未检测恶意锚，这是其缺少加密证明信任根的预期风险，不能暗改参考锚来制造通过。
- 同模型和物理路径，`theta_shadow`始终仅供离线诊断，攻击事件真值从不传给控制器的Gate、代理、部署更新。压力测试单独输出44通道诊断，新增 `stress_case`、`stress_active`、`checkpoint_tampered`、`checkpoint_anchor_error`。
- **验收**：独立Python审计必须校验3份原始ZIP与SHA256、全部72条×480点轨迹、三种攻击注入时间段及强度（检查点0.12L2）、完整性、actual deployed到**未污染**离线同算子动态影子的误差、攻击真实停止时e>0.001后进入0.001并保持20点、相邻和10步全部误差窗口、更新/Gate、归一化物理响应L1、控制L2、采样越界、受损检查点下失败次数。不以零样本违反、未触发重入、无动作危险提议冒充安全认证。
- 本压力实验不存在新形式证明，不含长时间物理真实状态跨步区间覆盖证书；结果不等于G3/G5证明，不可与未注入不同攻击的标准确认率混为一个统计分母。
